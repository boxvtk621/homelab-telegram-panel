# HL-240: контракт интерфейса рабочего места агента

## Продуктовая рамка

**Пользователь и задача:** оператор ежедневно выбирает агентскую сессию,
отправляет сообщение, следит за ответом и вмешивается, когда агент ждёт решения
или работает нештатно.

**Первый объект чтения:** текущий диалог и состояние выполняемой работы.

**Главное действие:** отправить сообщение в выбранный диалог.

**Плотность:** рабочая, умеренно компактная. Диалоги, сообщения и ход работы
видны одновременно на широком экране; показатели агента занимают одну компактную
полосу и не отодвигают чат.

**Иерархия:** сообщения и поле ввода → текущие инструменты и запросы решения →
список диалогов → состояние, очередь и технические идентификаторы.

**Модель взаимодействия:** трёхчастное рабочее место: сессии слева, чат в центре,
живой журнал справа. На узком экране порядок меняется на чат → ход работы →
диалоги; быстрые ссылки «Чат / Ход работы / Диалоги / Агент»
остаются в начале рабочего места. Сессионная плашка оператора скрывается внутри
мобильного рабочего места как дублирующая; история получает собственную прокрутку,
чтобы поле сообщения оставалось в первом экране.

**Запрещённые шаблоны:** декоративные KPI-карточки, mint/green как основной цвет,
градиенты и glassmorphism, одинаковый вес всех секций, hero-блок над работой,
UUID и protocol values как основной текст, имитация терминала для обычного чата.

## Переносимые продуктовые паттерны

- [Cursor Agent](https://cursor.com/docs/agent/overview): сообщение остаётся
  главным способом управления, а очередь и немедленное вмешательство показаны
  рядом с активной работой.
- [Cursor Browser](https://cursor.com/docs/agent/tools/browser): действия и
  результаты агента образуют проверяемый журнал, но подробные логи не заменяют
  сам диалог.
- [Linear My Issues](https://linear.app/docs/my-issues): списки сортируются и
  визуально взвешиваются по текущей работе, а не по равному набору карточек.
- [GitHub Actions logs](https://docs.github.com/actions/monitoring-and-troubleshooting-workflows/using-workflow-run-logs): подробности выполнения раскрываются по требованию;
  состояние и проблемный шаг остаются различимыми до раскрытия технического
  содержимого.

Эти источники задают не внешний вид, а модель: разговор — основной объект,
активность — соседний доказательный слой, техническая диагностика — раскрываемая.

## Цвет и типографика

До изменения зелёный использовался одновременно как фон, акцент, рамка, кнопка
и успешный статус. Это стирало семантику статусов и делало light/dark темы
монохромными.

| Роль                            | Было                   | Стало, light                 | Стало, dark                  |
| ------------------------------- | ---------------------- | ---------------------------- | ---------------------------- |
| Холст                           | `#eef3f0` mint         | `#f3f1ed` warm off-white     | `#111319` charcoal           |
| Поверхность                     | `#ffffff` / green tint | `#ffffff` / `#f7f7f5`        | `#1b1e25` / `#22262f`        |
| Основной текст                  | `#17231e` green-black  | `#202632` graphite           | `#f0f2f6`                    |
| Интерактивный акцент            | `#0b664a` green        | `#315fce` cobalt             | `#8aa7ff`                    |
| Выбранный объект                | `#dff1e8` mint         | `#eaf0ff` blue tint          | `#253456` slate-blue         |
| Успех / предупреждение / ошибка | green / amber / red    | только семантические статусы | только семантические статусы |

Системный sans-serif применяется для сообщений и управления. Monospace
используется только внутри кода и раскрытых технических деталей.

## Терминология первого слоя

| Протокольный термин                    | Текст оператора                                                  |
| -------------------------------------- | ---------------------------------------------------------------- |
| `Harness workspace`                    | Рабочее место                                                    |
| `node`                                 | агент                                                            |
| `ACTIVE DIALOG`                        | текущий диалог                                                   |
| `CONTROL` / attempt timeline           | ход работы                                                       |
| `tool.started` / `tool.output`         | вызов инструмента / ответ инструмента                            |
| `waiting_input`                        | ждёт решения                                                     |
| `attempt.stop`                         | остановить работу                                                |
| `queue.resume`                         | продолжить очередь                                               |
| `effect none/known/unknown`            | внешних изменений нет / подтверждены / состояние не подтверждено |
| `redaction applied`, `truncated`       | часть данных скрыта / показан сокращённый результат              |
| `usage per_attempt/cumulative_process` | за этот запуск / накопительно для процесса                       |
| UUID, `commandId`, `actionHash`, `seq` | раскрываемые «Технические детали»                                |

Cursor и Codex остаются именами движков. Протокольные коды сохраняются для
диагностики, но не конкурируют с задачей пользователя.

## Состояния и доступность

- Light и dark темы используют одинаковую иерархию; зелёный, янтарный и красный
  зарезервированы за состояниями.
- Основной текст и интерактивные элементы должны проходить WCAG AA; focus ring
  всегда видим и не зависит от цвета статуса.
- Touch targets — не меньше 44 px. Горизонтальное переполнение страницы
  запрещено; длинный код прокручивается внутри блока.
- Загрузка, пустой результат, ошибка, ожидание ответа, запрос разрешения и потеря связи
  должны оставлять понятное следующее действие.
- Markdown применяется только к inline-ответам агента. Сообщения пользователя и
  tool output не интерпретируются. Raw HTML игнорируется, `javascript:` и прочие
  небезопасные ссылки не становятся ссылками. Markdown-изображения показываются
  как безопасные ссылки и не загружаются автоматически.

## Finish evidence

- Скриншоты 1280 px и 1440 px в light theme.
- Скриншоты 390 px в light и dark themes.
- Учебные потоки: чат и очередь; вызовы инструментов; ожидание ответа;

- Проверка page errors, горизонтального overflow, keyboard focus и поведения
  длинного code block.
- Frontend typecheck, lint, tests, build и byte-for-byte embedded assets check.
